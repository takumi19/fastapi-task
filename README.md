# Сервис сокращения ссылок — ДЗ 3 и 4

Сервис на FastAPI: можно сократить ссылку, задать свой короткий адрес, посмотреть статистику переходов, изменить исходный URL или удалить ссылку. можно указать срок действия. Дополнительные функции из ДЗ 3 не делал.

Для работы с БД используется SQLAlchemy. При локальном запуске данные лежат в SQLite, а в Docker Compose настроен PostgreSQL. Redis используется для кэша. Тесты из ДЗ 4 находятся в этой же папке.

## Как запустить

Нужны Python и установленный Redis.

```bash
python -m pip install -r requirements.txt
python init_env.py
```

`init_env.py` создаст `.env` со случайными секретами. В отдельном терминале запускаем Redis:

```bash
redis-server --bind 127.0.0.1 --port 6379 --save '' --appendonly no
```

Если `redis-cli ping` уже возвращает `PONG`, Redis повторно запускать не надо.
После этого запускаем API:

```bash
python -m uvicorn src.main:app --host 127.0.0.1 --port 8000
```

Если используется окружение из корня этого проекта, вместо `python` можно писать
`python`.

Документация с возможностью отправлять запросы: http://127.0.0.1:8000/docs. Проверить подключение к БД и Redis можно через http://127.0.0.1:8000/health. Остановка — `Ctrl+C` в терминале с процессом.

## Запуск через Docker

Из той же папки:

```bash
python init_env.py
docker compose up --build -d
```

Будут запущены API, PostgreSQL и Redis. Документация также доступна на порту 8000.
Логи приложения:

```bash
docker compose logs -f api
```

Остановка:

```bash
docker compose down
```

Данные PostgreSQL сохраняются в Docker volume. Если добавить `-v` к команде остановки, этот том тоже удалится.

## Что есть в API

| Метод | Адрес | Что делает |
| --- | --- | --- |
| POST | `/auth/register` | Регистрация |
| POST | `/auth/login` | Получение токена |
| POST | `/links/shorten` | Создание короткой ссылки |
| GET | `/links/{short_code}` | Переход на исходный URL |
| GET | `/links/{short_code}/stats` | Статистика ссылки |
| GET | `/links/search?original_url=...` | Поиск по исходному URL |
| PUT | `/links/{short_code}` | Замена исходного URL |
| DELETE | `/links/{short_code}` | Удаление ссылки |

Редирект также работает по адресу `/{short_code}`, как во вводном примере задания.

Создавать и открывать ссылки можно без регистрации. Но чтобы потом изменить или удалить свою ссылку, нужно создать её с токеном авторизации. Управлять чужими ссылками нельзя. У анонимной ссылки нет владельца, поэтому изменить или удалить её через API не получится.

В Swagger можно сначала зарегистрироваться через `/auth/register`, а затем нажать **Authorize** и ввести логин и пароль. После этого токен будет добавляться к запросам автоматически.

## Примеры запросов

Регистрация:

```bash
curl -X POST http://127.0.0.1:8000/auth/register \
  -H 'Content-Type: application/json' \
  -d '{"username":"alice","password":"example-password-123"}'
```

Получение токена:

```bash
TOKEN=$(curl -sS -X POST http://127.0.0.1:8000/auth/login \
  --data-urlencode 'username=alice' \
  --data-urlencode 'password=example-password-123' \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["access_token"])')
```

Создание ссылки со своим alias:

```bash
curl -X POST http://127.0.0.1:8000/links/shorten \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"original_url":"https://example.org/article","custom_alias":"my-article"}'
```

Если не передать `custom_alias`, код сгенерируется автоматически. Свой alias должен быть уникальным и содержать от 3 до 32 символов: латинские буквы, цифры, `_` или `-`. Регистр учитывается. Слова вроде `search` и `shorten` заняты служебными маршрутами.

Для ссылки со сроком действия в JSON можно добавить поле:

```json
"expires_at": "2030-01-01T12:30:00Z"
```

Дату нужно заменить на нужную будущую минуту. Секунды должны быть нулевыми.
`Z` означает UTC; если часовой пояс не указан, тоже используется UTC.
Без этого поля ссылка хранится бессрочно.

Переход по ссылке, статистика и поиск:

```bash
curl -i http://127.0.0.1:8000/links/my-article
curl http://127.0.0.1:8000/links/my-article/stats
curl -G http://127.0.0.1:8000/links/search \
  --data-urlencode 'original_url=https://example.org/article'
```

Первый запрос вернёт `307` и исходный адрес в заголовке `Location`. В статистике будут исходный URL, дата создания, срок действия, число переходов и дата последнего перехода. Просмотр статистики не увеличивает счётчик. Поиск возвращает список, поскольку на один URL может быть несколько коротких ссылок.

Замена исходного URL и удаление:

```bash
curl -X PUT http://127.0.0.1:8000/links/my-article \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"original_url":"https://example.org/new-article"}'

curl -X DELETE http://127.0.0.1:8000/links/my-article \
  -H "Authorization: Bearer $TOKEN"
```

Основные ошибки: `401` — проблема с авторизацией, `403` — нет прав на ссылку,
`404` — ссылка не найдена или истекла, `409` — занят alias или логин,
`422` — неверные входные данные.

## Как хранятся данные

В БД две таблицы:

- `users`: ID, логин, хэш пароля и дата регистрации.
- `links`: ID, короткий код, исходный URL, владелец, даты создания и истечения,
  количество переходов, дата последнего перехода и версия записи.

Таблицы создаются при запуске. Для короткого кода и логина есть ограничения уникальности, для поиска по URL — индекс. Локальная БД находится в `data/links.db`. Даты хранятся в UTC. Пароли хэшируются через Argon2, для авторизации используется JWT со сроком действия 60 минут.

В `.env` можно задать `DATABASE_URL`, `REDIS_URL`, `SECRET_KEY` и `PUBLIC_BASE_URL`. Последний параметр нужен, чтобы в ответах возвращался правильный адрес короткой ссылки. При размещении на сервере его нужно поменять с localhost на адрес сервиса.

## Кэш и срок действиpя

Redis хранит исходный URL, ID и версию ссылки. Время хранения в кэше — до 5 минут, но не дольше срока действия самой ссылки. При обновлении или удалении ссылки её ключ удаляется из Redis.

Проверить кэш можно по заголовку `X-Cache`: первый переход обычно возвращает `MISS`, повторный — `HIT`. При каждом переходе счётчик всё равно обновляется в БД. Там же проверяется версия записи, чтобы после изменения ссылки не использовать старое значение из кэша. Если Redis недоступен, редиректы продолжают работать через БД.

Истёкшая ссылка сразу перестаёт работать и возвращает `404`. Фоновая задача каждые 5 секунд удаляет такие записи из БД и кэша. Очистка также выполняется при старте.

## Тесты — ДЗ 4

Установка зависимостей и запуск из этой папки:

```bash
python -m pip install -r requirements-dev.txt
python -m coverage run -m pytest tests
python -m coverage report
python -m coverage html
```

Получилось **72 теста**, все проходят. Покрытие с учётом ветвей — **99.55%**. Тесты используют временную SQLite БД и fakeredis, поэтому для них не нужно запускать отдельные сервисы.

Также есть нагрузочные сценарии Locust: массовое создание ссылок и редиректы с кэшем и без него. В локальных прогонах выполнено **164 679 запросов без ошибок**. Счётчики в БД совпали с количеством завершённых запросов.

На этой конфигурации Redis не дал ускорения: медиана составила около 1050 запросов/с с кэшем и 1286 без него. При каждом редиректе всё равно выполняется запись в SQLite, а обращение к Redis добавляет ещё один запрос. Эти результаты относятся к локальному запуску, для PostgreSQL на сервере результат может отличаться.
