# Нагрузочное тестирование

Проверялись два сценария: создание новых ссылок и переходы по уже созданным. Для нагрузки использовался Locust. Каждый запуск длился 20 секунд, число пользователей увеличивалось до 20 со скоростью 10 пользователей в секунду. Пауз между запросами не было.

Для редиректов заранее создавались 64 ссылки и заполнялся кэш. Затем выполнялись по три запуска с Redis и без обращений к нему. Порядок запусков чередовался. Сам редирект проверялся по статусу 307 и заголовку Location, на внешний сайт запрос не переходил.

Все замеры сделаны локально 15 сентября 2026 года: macOS, Python 3.14.7, FastAPI 0.141.1, SQLite 3.53.4, Redis 8.10.1 и Locust 2.46.5. API работал с одним Uvicorn worker. Для каждого запуска создавалась отдельная временная БД, поэтому рабочие ссылки не затрагивались.

Всего получилось **164 679 запросов, ошибок не было**. После каждого запуска проверялись данные в БД: число созданных ссылок совпало с числом успешных POST, а счётчики переходов — с числом редиректов, включая 64 перехода для заполнения кэша. Во всех замерах с кэшем редиректы возвращали `X-Cache: HIT`.

В таблице p95 и p99 — задержки, в которые укладываются примерно 95% и 99% запросов. Они заметно больше средней задержки, то есть часть запросов обрабатывалась существенно дольше остальных.

## Выводы

На этой конфигурации Redis не ускорил редиректы. Медиана по трём запускам составила **1049.62 запроса/с с кэшем** и **1285.95 без него** — с кэшем примерно на 18% меньше. Медиана средних задержек тоже оказалась выше: 18.43 мс против 15.07 мс.

Вероятное объяснение — при каждом редиректе всё равно выполняется SQL UPDATE для счётчика переходов и проверки версии ссылки. Кэш не убирает эту запись, но добавляет обращение к Redis. Получение короткого URL из локальной SQLite в данном случае обходится дешевле.

Эти результаты относятся только к коротким локальным прогонам. Генератор нагрузки, API и Redis работали на одном компьютере. Для PostgreSQL на отдельном сервере или для более долгой нагрузки результаты могут отличаться.

## Как повторить

Нужен запущенный Redis.

```bash
python load_tests/run_load.py --seconds 20 --repeats 3 --users 20
```

Скрипт сохранит новые результаты в `reports/load/`. Этот текстовый отчёт автоматически не обновляется.

Числа в таблице взяты из [results.json](results.json). Финальные счётчики также сохранены в `*_final_stats.csv`. Обычные `*_stats.csv` содержат периодические снимки Locust и могут не учитывать последние ответы при остановке, поэтому для сравнения с БД использовались финальные значения.
